# Reference deconstruction

## Purpose

Study references for transferable design logic. Synthesize lessons into the current brand. Never reproduce the source's identity.

> Extract the underlying design logic. Do not reproduce the source's layout, assets, copy, colors, typography combination, illustrations, or signature compositions.

## When to invoke

- User supplies a website, screenshot, product, artwork, editorial, architecture, fashion, or film reference
- During Phase 2 creative exploration alongside `creative-director`
- Before adopting a layout or motion pattern "because it looked good"
- When team wants to "make it feel like [reference]"

## Required inputs

- Reference material (URL, screenshot, or description)
- Current creative thesis and approved direction (if any)
- Product context and brand constraints
- Explicit question: what are we trying to learn?

## Step-by-step workflow

### 1. Observe without copying

For each reference, analyze:

| Lens | Questions |
| --- | --- |
| Emotional effect | What feeling does it create? |
| Underlying design logic | What rules organize the whole? |
| Grid | Column logic, breakpoints, alignment |
| Composition | Focal points, asymmetry, overlap |
| Whitespace | Ratio of quiet to dense |
| Typography | Role separation, scale jumps, character |
| Hierarchy | What reads first, second, third |
| Density | Information per viewport |
| Pacing | How sections change rhythm |
| Repetition | Motifs and anchors |
| Contrast | Light/dark, scale, weight |
| Color behavior | Relationships, not hex copying |
| Materiality | Flat, textured, photographic |
| Motion | What moves and why |
| Interaction | Signature behaviors |
| Product presentation | Demo, screenshot, abstract |
| Signature techniques | What makes it memorable |
| Category clichés | What it shares with competitors |
| Transferable principles | Logic we can adapt |
| Non-transferable identity | What we must not take |

### 2. Separate learn from copy

| Learn | Do not copy |
| --- | --- |
| Pacing logic, tension devices, type hierarchy | Exact layout, palette, font pairing |
| Whitespace discipline | Logo placement, hero structure |
| Motion causality | Illustration style, photography |

### 3. Synthesize

Do not average references. Combine principles into one coherent lesson for **this** brand.

### 4. Translate

Explain how the lesson becomes fajita-io:

- What changes in our composition, type, or motion
- How the result stays unmistakably original
- What we explicitly reject from the reference

### 5. Record rejections

Add non-transferable elements and tempting copies to rejected patterns.

## Required outputs

- **Reference analysis** (per source)
- **Transferable principles** (bulleted, actionable)
- **Non-transferable elements** (explicit do-not-copy list)
- **Translation plan** for current brand
- **Originality check** (why result will not read as imitation)

## Quality gates

- [ ] Analysis covers design logic, not just adjectives
- [ ] No recommendation to copy layout, palette, or type combo from source
- [ ] Translation ties to `creative-thesis.md`
- [ ] Rejected imitation patterns logged

## Failure conditions

- "Make it look like Linear/Stripe/Apple"
- Output that recreates reference hero structure
- Averaging three references into generic mush
- Skipping non-transferable identity section

## Design memory updates

| File | What to write |
| --- | --- |
| `creative-thesis.md` | Insights that refine thesis or conventions |
| `rejected-patterns.md` | Reference-specific things we will not copy |
| `visual-decisions.md` | Adopted principles with source attribution (internal only) |

## Do not code yet

Use analysis to inform `creative-director` territories. Do not implement reference layouts directly.

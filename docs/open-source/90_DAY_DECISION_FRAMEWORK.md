# 90-day decision framework

At approximately 90 days after OSS launch, classify Fajita into one bucket and document the decision.

Review date: _______________

## Bucket A: Traction

OSS, community, or revenue is working.

**Indicators (need several, not one):**

- 500+ GitHub stars with sustained velocity, or strong Docker/adoption signal
- 3+ external recurring contributors
- $500+ Cloud MRR or clear OSS → Cloud conversion
- Material organic traffic or backlinks
- Credible commercial interest

**Action:** Consider renewed investment. Update ROADMAP.md with scoped priorities. Do not automatically restart a full product roadmap.

## Bucket B: Quiet compounder (default)

Small but positive or neutral activity. Operating cost is acceptable.

**Indicators:**

- Low but non-zero GitHub activity
- SEO and content compounding slowly
- Cloud runs without founder attention
- No serious security or support burden

**Action:** Continue [MAINTENANCE_MODE.md](./MAINTENANCE_MODE.md). Refresh TrustMRR only if metrics materially improved.

## Bucket C: Dead

No meaningful usage, traffic, contributors, Cloud revenue, or acquisition interest.

**Indicators:**

- Near-zero GitHub engagement
- No self-host reports
- Cloud MRR flat at zero or negligible
- No inbound commercial interest

**Action:** Keep domain, repo, and Cloud online if cost is negligible. Do not shut down reflexively. Stop all proactive work. Revisit annually or on inbound inquiry.

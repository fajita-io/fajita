# GitHub Discussions structure

Enable Discussions when the repository becomes public. Keep the issue tracker for actionable bugs and features.

## Categories

| Category | Purpose |
| --- | --- |
| **General** | Community conversation about Fajita and uptime monitoring |
| **Ideas** | Feature ideas that need discussion before an issue |
| **Q&A** | Help for self-hosting and configuration (community answered) |
| **Show and tell** | Deployments, integrations, and creative uses |
| **Integrations** | Slack, Discord, webhooks, email, and automation patterns |

## Boundaries

- **Issues:** reproducible bugs, accepted feature work, documentation fixes with clear scope
- **Discussions:** questions, brainstorming, open-ended help, sharing setups
- **Security:** never in public Discussions; use [SECURITY.md](../../SECURITY.md)

## Moderation

- Move misplaced bug reports from Discussions to Issues with a link
- Close spam and off-topic threads
- Pin a welcome post linking to README Quick Start and docs index

## Launch task

Repository admin: Settings → General → Features → Discussions → Enable, then create categories above.

# Reactivation thresholds

Measurable signals that justify renewed active product investment in Fajita. Until a threshold is crossed, remain in [MAINTENANCE_MODE.md](./MAINTENANCE_MODE.md).

## GitHub

| Signal | Threshold |
| --- | --- |
| Stars | 500+ sustained interest, or 1,000+ |
| Star velocity | Meaningful week-over-week growth for 4+ weeks |
| External contributors | 3+ recurring non-founder contributors with merged PRs |

## Usage

| Signal | Threshold |
| --- | --- |
| Self-host adoption | Recurring GitHub issues from real deployments |
| Docker pulls | Meaningful pull growth if GHCR analytics available |
| Install feedback | Multiple independent successful self-host reports |

## Traffic

| Signal | Threshold |
| --- | --- |
| Organic search | Material growth to `/open-source` or self-host docs |
| GitHub referral | Sustained referral traffic to fajita.io from github.com |

## Revenue

| Signal | Threshold |
| --- | --- |
| Cloud MRR | $500+ MRR |
| Cloud customers | Several independent paying Cloud customers |
| OSS → Cloud conversion | Measurable signup lift from OSS pages (`cloud_from_oss_clicked` goal) |

## Commercial

| Signal | Threshold |
| --- | --- |
| Partnership | Serious integration or distribution partnership |
| Acquisition | Credible offer with substantive diligence |
| Community | Maintainer or foundation opportunity with clear upside |

## What does not trigger reactivation

- One feature request from one user
- A single HN comment thread
- Vanity star count without usage or revenue signal
- Competitor launch anxiety

## Review cadence

- **30 days:** [30_DAY_REVIEW.md](./30_DAY_REVIEW.md)
- **90 days:** [90_DAY_DECISION_FRAMEWORK.md](./90_DAY_DECISION_FRAMEWORK.md)

## Decision

When multiple thresholds from different categories align, document the decision in a short internal note and update ROADMAP.md scope accordingly. Do not restart full development for a single metric spike.
